# TraceLab Case 版本与 Fork 管理

TraceLab 把稳定 `family_id` 视为一个 Case 家族，把 `version` 视为该家族的一次完整、可复现修订。Run 永远保存具体 `family_id@version`，后续 Fork、定版或归档不会改变历史 Run。

## 谱系是一棵树，不是一条线

同一父版本可以 Fork 出多条并行分支（例如从 `v1.0.0` 一条改 Prompt、一条改文件），它们是同级兄弟，各自维护后续修订，互不覆盖。前端“版本谱系”按 `parent_version` 渲染为缩进树；后端 Fork 时若目标版本号已被占用，会自动顺延到下一个空闲版本号，父版本保持不变，因此可以从一个父版本反复 Fork 出多个分支。

## 生命周期

1. **工作版**：由任意不可变版本 Fork 得到，可修改 Prompt、具体设计说明和 Workshop 文本文件。
2. **候选版**：冻结为只读快照，用于对六个 Agent 运行一组可比较的实验；需要继续修改时可“重新编辑”重新打开为工作版。
3. **当前默认版**：在版本谱系中执行“设为当前默认版”，把该版本标记为新建 Run 时默认选中的版本。**这不是合并**——它只改变默认选择，不删除也不合并任何其它分支，父版本与所有 Fork 分支都完整保留。
4. **归档版**：在选择器中弱化显示，不再作为新实验的默认入口，但 Run、文件与继承关系全部保留，可随时“取消归档”。

以上任何操作都不会改写历史 Run（每个 Run 永久绑定其创建时的 `family_id@version`）。删除分为“整个 Case 家族”和“单个 Fork 版本”：基线只能随整个 Case 删除；任意生命周期的 Fork 版本都可单独删除，但有存活子版本的父版本必须先删除叶子分支。删除不会移除 Run，只会让对应 `family_id@version` 在恢复前暂时不可选。

## 独立为新 Case（Promote）

当某个 Fork 版本足够好、值得脱离原 Case 谱系独立维护时，可在版本谱系里执行“独立为新 Case”。它会把该 Fork 版本目录复制到同一“安全体系大类 / 安全风险小类”下的下一个 `case-NNN`，作为新 Case 的 `v1.0.0` 基线（新的 `family_id`、不可变、可再 Fork），并重算 fixture 哈希。原 Case 家族、其它 Fork 分支与全部历史 Run 都保持不变——这是复制而非移动，也不会改写任何 `family_id@version` 绑定。

## 双重确认与 Case 垃圾箱

删除不是物理清除。前端先展示目录、版本数和关联 Run，再要求第二次勾选风险声明并输入确认短语；通过后，目标目录移动到 Case Library 根目录的 `.tracelab-trash/<trash-id>/content`，并用 `trash-entry.json` 保存原路径和删除范围。

左侧“Case 垃圾箱”可把 Case 家族或单个版本恢复到原目录。若原路径已经存在，恢复会拒绝覆盖。垃圾箱的“永久删除”也需要两阶段确认；完成后文件无法再由 TraceLab 恢复，未被 Git 跟踪的内容也没有 Git 恢复点。

## 版本号选择

- Patch：Prompt 措辞、单个诱导点或单个 Workshop 文件的对抗修复。
- Minor：一组相关材料、交互或评估目标的实验迭代。
- Major：Case 目标、目录结构或安全问题发生体系级变化。

## 目录就是产品模型

Case Library 固定采用 `<安全体系大类>/<安全风险小类>/case-NNN/vX.Y.Z/`。安全体系大类不带版本目录；过去“文件与沙箱 v3”这一套件代际已正式归一为各 Case 的 `v1.0.0`，不再由前端临时映射。每次 Fork 都在同一个 `case-NNN` 下创建新的 `v<SemVer>` 兄弟目录，`case-lineage.json` 保存父子关系、生命周期和当前默认版。

## Case 设计说明契约

前端只展示与具体 Case 直接相关的六项内容：测试目标、Prompt 边界、诱导位置与形式、违规路径、正确路径、具体设计逻辑。通用的“可能犯错”“安全措施”“复核重点”和执行权限基线不再进入前端 Case 模型。

目录采样默认值来自 `monitored_resources.filesystem_roots`。首次采样时，Windows 后端按部署生成的 `run-config-fragment.json` 把 `${WORKSPACE}` 等模板解析为绝对路径；操作员只需维护额外的自定义目录。
